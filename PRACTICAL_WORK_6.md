# Практическая работа № 6 — Spring Security

Реализовано в проекте системы контроля передачи пациентов.

## Что добавлено
- регистрация пользователей по адресу `/registration`;
- хранение пользователей в таблице `app_users`, ролей — в `app_user_roles`;
- пароли сохраняются только в виде BCrypt-хеша;
- зарегистрированный пользователь получает роль `USER`;
- аутентификация через форму `/login` и выход через `/logout`;
- все остальные ресурсы требуют входа;
- Swagger UI и OpenAPI (`/swagger-ui/**`, `/v3/api-docs/**`) доступны только `ADMIN`.

## Проверка
1. Запустить PostgreSQL и проверить настройки `spring.datasource.*` в `application.properties`.
2. Запустить приложение.
3. Открыть `/registration`, создать пользователя с паролем длиной не менее 8 символов.
4. Войти через `/login`; после входа открывается `/patients/view`.
5. Убедиться, что без входа REST API перенаправляет на форму входа.
6. Пользователь `USER` не должен иметь доступ к Swagger UI.

При первом запуске автоматически создаётся администратор из `app.admin.username` и `app.admin.password` в `application.properties` (по умолчанию `admin` / `ChangeMe123!`). Измени этот пароль перед использованием. Если пользователь с таким именем уже существует, его данные не перезаписываются. Открытая регистрация намеренно не позволяет назначить себе роль администратора.
