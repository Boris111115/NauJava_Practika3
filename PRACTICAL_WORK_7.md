# Практическая работа № 7 — Многопоточность и асинхронность

Реализация добавлена в существующий проект NauJava (практические работы № 5–6).
Существующая конфигурация Spring Security и остальные функции проекта сохранены.

## Что добавлено

- `entity/Report.java` — сущность отчёта: числовой ID, статус, HTML-содержимое.
- `entity/ReportStatus.java` — статусы `CREATED`, `COMPLETED`, `ERROR`.
- `repository/ReportRepository.java` — JPA-репозиторий.
- `service/ReportService.java` — создание, получение и асинхронное формирование отчёта.
- `web/ReportRestController.java` — REST API.

Для статистики выбраны пользователи (`User`) и передачи пациентов (`PatientTransfer`).
Подсчёт пользователей и получение списка передач выполняются в двух отдельных `Thread`.
Метод `join()` ожидает завершения обоих потоков. Само формирование запускается через
`CompletableFuture.runAsync`, поэтому POST-запрос не ждёт готовности HTML.

## REST API

Все запросы подчиняются существующей настройке Spring Security: необходимо войти в систему.

### 1. Создать отчёт

`POST /custom/reports`

Ответ: HTTP 202 Accepted, например:

```json
{
  "id": 1,
  "status": "CREATED",
  "message": "Отчёт создан. Для получения результата запросите GET /custom/reports/1"
}
```

### 2. Получить отчёт

`GET /custom/reports/1`

- Пока отчёт формируется: HTTP 202 и JSON со статусом `CREATED`.
- При ошибке: HTTP 500 и JSON со статусом `ERROR`.
- После завершения: HTTP 200 и HTML-страница со статистикой и таблицей передач пациентов.

## Проверка

1. Запустить PostgreSQL и убедиться, что параметры подключения в `application.properties`
   соответствуют локальной базе данных.
2. Запустить приложение.
3. Авторизоваться существующим пользователем.
4. Выполнить `POST /custom/reports`.
5. Сохранить полученный `id` и периодически выполнять `GET /custom/reports/{id}`.
6. После получения HTML-страницы проверить количество пользователей, список передач и три значения времени.

Таблица `reports` создаётся/обновляется автоматически благодаря
`spring.jpa.hibernate.ddl-auto=update`.

## Важно
